# Phase 1 最终体验审计

## 结论

Phase 1 的完整产品切片已经成立：孩子可以从同一幅真实山河骨架进入 5 个地点，选择 10 首完整诗境，在 3 种阅读支持强度下看上方拼音、听全诗或逐句朗读、完成基于诗句证据的山风引导，并把结构化足迹留在本机。

## P0 根因与修复

原始拼音 DOM 的语义顺序正确，但旧 `.poem-line ruby` 被设为 `inline-flex; flex-direction: column`，浏览器不再执行 ruby 排版，而按 DOM 顺序先排汉字、后排 `rt`，所以拼音落在字下方。最终实现使用明确的两行 grid：`annotation` 在上、`base` 在下；浏览器 evaluator 逐个测量 `rt.bottom <= base.top + 2px`，不是只检查元素存在。

原始 AI 区域的根本问题是把阶段交互当成覆盖层。最终架构把诗、朗读和拼音放进 Primary Content；AI 在桌面占独立侧栏，在平板/手机成为诗后正常文档流。输入与键盘只影响 secondary 区，不会覆盖诗。

## 主动 critique 后的再修改

1. 五个地图标签在中国东部集群发生真实重叠：错开标签方向并加入几何重叠检查。
2. 768×1024 先出现说明、地图落到折叠下：调整为地图优先。
3. 390×844 地点说明先于诗，诗只能看见一半：移动端改为诗优先，完整四句/八句进入首屏。
4. 手机拼音最小 9.27px：提高到 10.88px。
5. 八句诗的逐句朗读按钮只有 41px 高：提高到 44px。
6. 150% 文本缩放产生 10px 内部水平溢出：按大字模式收紧 ruby 间距并通过复验。

## 新发现

本轮发现的主要新问题不是新增功能缺失，而是“好看的单屏构图”在八句诗、平板竖屏、大字模式和东部地点集群中会失效。已经把这些从一次性截图问题转成可重复 evaluator 规则。未来真实儿童测试仍应关注：低龄孩子是否理解“山风回应”、不同年龄的完成标准是否过严、生成场景图是否帮助空间记忆而不是只增加气氛。
